# 핵심만 남기는 프롬프트

사용자의 긴 설명이나 기존 프롬프트를 짧고 바로 사용할 수 있는 요청문으로 만든다. 이 스킬만으로 처리 가능한 요청에는 검색·문서 변환·다른 스킬을 추가하지 않는다.

## 작성

- 실제 목표와 원하는 결과부터 파악한다. 요청문을 작성하는 일과 그 안의 작업을 수행하는 일을 구분한다.
- 목표, 답에 꼭 필요한 사실·자료, 필수 조건, 원하는 출력만 남긴다. 이미 짧고 충분하면 억지로 바꾸지 않는다.
- 인사·반복 강조·동일한 설명·불필요한 역할 부여·장황한 배경·사용자가 요구하지 않은 절차와 예시는 제거한다.
- 숫자·단위·날짜·범위·부정 조건·예외·사용자 정정·출처·미해결 사항 중 결과에 영향을 주는 것은 보존한다. 인용문·코드·정확한 명칭은 의미를 바꾸며 줄이지 않는다.
- 문맥 없이 다른 채팅에 붙여도 이해되게 쓴다. '위 내용', '앞서 말한 것' 대신 필요한 대상을 명시한다. 링크만으로 접근 가능하다고 가정하지 않는다.
- 기존 대화에서 확인되는 정보는 다시 묻지 않는다. 결과를 바꾸는 핵심 정보가 없을 때만 짧게 확인한다. 추측으로 조건을 추가하지 않는다.
- 기본은 1~3문장 또는 핵심 항목 3~5개다. 필요한 조건이 많으면 길이보다 보존을 우선한다. 사용자가 지정한 길이와 형식이 우선한다.
- 축약어·난해한 기호·번역으로 글자 수만 줄이지 않는다. 읽기 쉬운 한국어를 기본으로 한다.

## 출력

완성된 프롬프트 한 개만 출력한다. 소개, 작성 과정, 장점 설명, 중복 요약, 여러 버전, 후속 제안은 요청받았을 때만 추가한다. 짧은 요청은 제목이나 양식 없이 한 문장으로 쓴다.

복잡할 때만 목표 / 필수 정보·조건 / 결과의 세 부분으로 나눈다. 해당 없는 칸과 자리표시자를 만들지 않는다. 불가피한 조건 충돌이나 누락은 짧게 드러낸다.

마지막으로 원래 요구사항과 대조해 목표·수치·금지 사항·출력 조건이 빠지거나 반대로 바뀌지 않았는지 확인한다. 사용자에게 내부 검토 과정을 출력하지 않는다.

## 예시

입력: PDF가 너무 길어서 읽기가 힘들어. 시험 공부를 하려고 하는데 외부 지식은 필요 없고 교수님 자료만 써줘. 12쪽부터 18쪽까지 핵심을 뽑아서 표로 보고 싶고 어느 페이지인지도 알려줘.

출력: 첨부 PDF 12~18쪽의 시험 복습용 핵심을 표로 정리해줘. 제공 자료만 사용하고 항목별 페이지를 표시해줘.

입력: 10월 31일까지 제출할 보고서인데 1000자 이내로 써야 해. 단, 참고문헌은 글자 수에서 제외해. 일단 이 요청을 짧은 프롬프트로 만들어줘.

출력: 10월 31일 제출용 보고서를 참고문헌 제외 1,000자 이내로 작성해줘.

## 사용량 경계

짧은 출력과 불필요한 호출 감소를 목표로 한다. 글자 수 감소를 토큰 절감률로 표현하지 않는다. 전체 사용량은 작성 처리·대화 문맥·재시도까지 영향을 받으므로 실제 측정 없이 비용이나 절감률을 보장하지 않는다.

자료 기반 작성에 추가 기준이 필요할 때만 [공통 프롬프트 작성법](../PROMPT_GUIDE.md)을 참고한다.
