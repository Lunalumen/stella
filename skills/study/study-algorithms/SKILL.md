# 알고리즘과 프로그래밍 공부

[출처 원칙](../../sources/read-and-summarize/references/source-rules.md)을 따른다. 수업 언어·문법·풀이 방식·표기를 우선한다.

## 학생이 푼 문제와 개념 연결

학생이 따로 풀고 답을 제출하는 방식에서는 오답 검토를 기본으로 한다. 다음 문제·새 문제·복습 퀴즈를 자동으로 내지 않는다. 직접 요청한 범위만 다룬다.

1. 장·문제지·문항 번호·학생 답을 식별한다. 현재 문맥으로 식별할 수 있으면 다시 묻지 않는다. 미제출 문항의 정답은 노출하지 않는다.
2. 해당 문항과 필요한 정답·해설만 읽고 채점한다. 해설이 없거나 잘못되었을 가능성이 있으면 해당 개념·코드로 검토하며, 자료의 정답과 자체 판단을 구분한다. 해설을 무조건 정답으로 취급하지 않는다.
3. 오답의 핵심 개념으로 슬라이드 색인/검색용 텍스트를 검색한 뒤 실제 PPTX의 관련 슬라이드만 확인한다. 파일명·슬라이드 번호·제목을 제시한다. 번호는 프레젠테이션의 실제 순서로 확인하며 검색용 텍스트 줄 번호나 PDF 페이지와 혼동하지 않는다. 관련 개념을 설명하는 슬라이드와 문제 자체가 있는 슬라이드를 구분한다.
4. 짧게 `문항·학생 답/정답 → 답이 틀린 근거 → PPT 파일·슬라이드·제목 → 다시 확인할 개념`을 연결한다. 선택지의 오류와 학생이 그 선택지를 고른 이유는 다르다. 답만으로 오류 원인을 단정하지 말고, 필요할 때만 풀이 생각을 한 번 묻는다.
5. 사용자가 지정한 개인 공부 기록에 문항 식별자·답·관련 위치·확인된 오개념/원인 미확인·복습 상태를 짧게 남긴다. 원문·전체 해설을 복사하지 않는다. 요약 확인을 학생 학습 완료로 처리하지 않는다.

## 반복 조회 비용 줄이기

- 연결된 자료 목록과 직전 기록에서 대상 파일을 찾고 제출 문항·관련 슬라이드만 읽는다. 매번 전체 문제지·강의자료·타 채팅을 다시 출력하지 않는다.
- DOCX 문항과 PPTX 검색/지정 슬라이드는 [조회 도구](scripts/algorithm_lookup.py)의 `--help`를 필요할 때 확인해 사용한다. 경로는 개인 작업 기록에서 받으며 스킬에 하드코딩하지 않는다. PDF·이미지 문제지는 해당 형식 도구로 대상 페이지를 확인한다.
- 색인/캐시를 재사용할 경우 파일 경로와 버전 지표를 대조한다. 원본 변경 시 관련 색인·슬라이드 연결만 갱신한다. 확정 설명과 슬라이드 번호는 현재 원본으로 검증한다. 도형·수식·코드 들여쓰기가 텍스트로 불명확하면 관련 슬라이드만 시각 확인하며 검증되지 않은 부분을 표시한다.
- 개선은 실제 드러난 반복 읽기·오진·잘못된 위치만 좁게 수정한다. 공부 기록에 `문제 근거 / 변경 / 검증 / 남은 일`만 남기고 스킬 전체를 매번 재작성하지 않는다.
- 에이전트는 독립된 다수 문항 검색·검토에 실제 이점이 있고 사용자가 허용했을 때 선택한다. 단일 문항에 매번 여러 에이전트를 실행하지 않는다. 위임은 대상 문항·자료 위치·출력 한도로 좁히고 결과 근거를 확인한다. 에이전트 사용 자체나 읽기량 감소를 토큰 절감률로 표현하지 않는다.

## 요청된 코드 설명·연습

- 코드 설명은 초기값·조건·변수 변화·반복 횟수·출력을 필요한 범위에서 추적한다. 학생이 예측할 문제의 추적 결과는 답변 뒤 공개한다.
- 새 문제 출제를 요청했을 때만 객관식·출력 예측·빈칸·오류 수정·코드 작성 중 시험에 맞는 유형을 선택한다. 정답·풀이 요청에는 바로 제공한다.
- 실행했으면 입력·관찰 결과를, 실행하지 않았으면 수작업 추적임을 표시한다. 실행 성공과 모든 입력의 정답성을 구분한다.
- 오류 원인은 근거가 있을 때 개념/암기/해석/계산·코딩 실수로 분류한다. 공부 계획·다른 과목 기능은 해당 요청이 있을 때만 사용한다.
